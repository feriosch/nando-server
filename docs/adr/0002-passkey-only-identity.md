# Passkeys are the only way to sign in; there is no password

The Owner signs in with a passkey (Face ID on iPhone, stored in Google Password Manager or iCloud Keychain; the server holds only public keys). There is deliberately no password, no login form and no password reset. A new passkey can only be registered with an Enrollment Code: a single-use code, valid for about 15 minutes, printed by a server CLI command (`nando-server enroll`) that needs access to the production database. The same command is the recovery path. We chose this because the Owner wants Face ID, will never change a password, and a password fallback would be extra code and attack surface for a login nobody uses.

## Consequences

- Signing in produces a server-side session: a random token in an `HttpOnly`, `Secure`, `SameSite=Lax` cookie scoped to the parent domain, so it covers both `web.` and `api.`. Only the token's hash is stored; the session also has a separate ID, so it can be listed and deleted without revealing the token. It lasts 90 days and renews on use, so Face ID is needed only when it expires. Deleting a session signs that device out.
- The passkey's relying-party ID is the parent domain, so passkeys survive any change to the `web.`/`api.` subdomain layout but not a change of domain. A new domain means enrolling again with an Enrollment Code.
- Passkeys can be used from every origin in `ALLOWED_ORIGINS`, the same list that may call the API with credentials (CORS), rather than only from `https://web.<DOMAIN>`. One list keeps local development simple (`http://localhost:5173` with `DOMAIN=localhost`) without a second setting to keep in step, and an origin trusted with the Owner's session cookie gains little from also running the passkey ceremony. A browser only offers a passkey to pages under its relying-party ID, so in practice only the origins in `ALLOWED_ORIGINS` that are under `DOMAIN` can use one. Adding an origin to `ALLOWED_ORIGINS` therefore also lets it sign in.
- The iOS Home Screen app keeps its cookies separately from Safari, so each needs its own sign-in.
